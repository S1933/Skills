# Philosophy

Technical debt is a cost or risk created by the current system in its actual context—not merely code that differs from a reviewer’s preferences.

Prioritize evidence-backed problems that affect correctness, security, change cost, operability, delivery speed, or supported users. Account for deliberate tradeoffs, repository age, migration state, and team conventions. Distinguish debt from defects, product opportunities, and harmless style differences.

A useful audit reduces uncertainty and produces executable next steps. It should also identify false positives and areas that were not inspected.

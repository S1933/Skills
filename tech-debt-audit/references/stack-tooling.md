# Stack-specific tooling

Discover commands from repository configuration before running them. Prefer existing lockfiles and project scripts.

Useful read-only categories include dependency vulnerability reports, compiler/typechecker diagnostics, linters, test coverage, dead-code analysis, duplicate detection, package age, and build configuration inspection. Run only tools already available or explicitly approved by the user.

Record the exact command, version when relevant, exit status, and scope. Tool output is evidence to investigate, not a finding by itself. Verify each reported issue in source before including it.
